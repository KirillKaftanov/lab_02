# StreamStats

Лабораторная работа № 2. Потоковый анализатор событий из файлов CSV и JSONL.

Программа читает входные файлы постепенно, проверяет записи и формирует статистический отчет в формате JSON.

## Возможности

- Подсчет общего количества корректных событий.
- Подсчет событий каждого уровня и каждого источника.
- Top-5 источников ошибок уровней ERROR и CRITICAL.
- Поиск самой ранней и самой поздней временных меток.
- Объединение статистики нескольких файлов одного формата.
- Остановка при ошибочной записи или ее пропуск с предупреждением.
- Сохранение отчета в файл или вывод в терминал.

## Подготовка к запуску

Требуются Python 3.12 или новее и установленный uv.

Все команды выполняются из корня проекта, где находятся `pyproject.toml`, `uv.lock`, `src` и `tests`.

На macOS/Linux:

```bash
uv sync --locked
source .venv/bin/activate
```

Команда `uv sync --locked` создает окружение `.venv`, если его еще нет, и устанавливает сам проект и зависимости из `uv.lock`, включая инструменты для проверки.

После открытия нового окна терминала нужно перейти в каталог проекта и снова активировать окружение:

```bash
source .venv/bin/activate
```

## Входные данные

Файлы должны быть в кодировке UTF-8. Поддерживается UTF-8 с BOM.

Каждое событие содержит четыре обязательных поля:

| Поле | Требование |
|---|---|
| `timestamp` | Строка с датой и временем через `T` в ISO 8601, например `2026-10-14T12:00:00Z` |
| `level` | Один из уровней: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `source` | Непустая строка; строка из одних пробелов не принимается |
| `message` | Строка, в том числе пустая |

Временные метки приводятся к UTC. Если часовой пояс не указан, время считается временем UTC.

### CSV

CSV с событиями должен содержать заголовок. Поля разделяются запятыми.

Пример содержимого `events.csv`:

```csv
timestamp,level,source,message
2026-10-14T12:00:00Z,INFO,app,Запуск программы
2026-10-14T13:00:00Z,ERROR,server,Ошибка подключения
```

Если сообщение содержит запятую, поле нужно заключить в двойные кавычки:

```csv
2026-10-14T14:00:00Z,WARNING,app,"Соединение потеряно, повторная попытка"
```

### JSONL

Каждая строка содержит один JSON-объект.

Пример содержимого `events.jsonl`:

```jsonl
{"timestamp": "2026-10-14T12:00:00Z", "level": "INFO", "source": "app", "message": "Запуск программы"}
{"timestamp": "2026-10-14T13:00:00Z", "level": "ERROR", "source": "server", "message": "Ошибка подключения"}
```

## Запуск

Справка:

```bash
python -m streamstats --help
```

Анализ CSV с сохранением отчета:

```bash
python -m streamstats analyze events.csv --format csv --output report.json
```

Анализ JSONL с сохранением отчета:

```bash
python -m streamstats analyze events.jsonl --format jsonl --output report.json
```

Объединение статистики нескольких файлов:

```bash
python -m streamstats analyze first.csv second.csv --format csv --output report.json
```

Пропуск некорректных записей:

```bash
python -m streamstats analyze events.jsonl --format jsonl --skip-invalid --output report.json
```

Вывод отчета в терминал:

```bash
python -m streamstats analyze events.jsonl --format jsonl
```

Имена входных файлов в командах нужно заменить на свои. Все файлы одного запуска должны соответствовать формату, указанному в `--format`.

Путь после `--output` должен отличаться от пути каждого входного файла, иначе исходные данные будут перезаписаны отчетом.

## Обработка ошибок

По умолчанию программа останавливается на первой некорректной записи, выводит в stderr путь к файлу и номер строки и завершается с кодом 2.

С флагом `--skip-invalid` некорректная запись пропускается, в лог записывается WARNING, а число пропусков добавляется в поле `skipped_lines` отчета.

Ошибки открытия файла и некорректный CSV-заголовок останавливают обработку даже с `--skip-invalid`. При незакрытой кавычке в CSV несколько физических строк могут быть прочитаны как одна поврежденная запись.

При успешном выполнении код завершения равен 0.

## Отчет

Для примера с двумя событиями из `events.csv` или `events.jsonl` отчет выглядит так:

```json
{
    "total_events": 2,
    "events_by_level": {
        "DEBUG": 0,
        "INFO": 1,
        "WARNING": 0,
        "ERROR": 1,
        "CRITICAL": 0
    },
    "events_by_source": {
        "app": 1,
        "server": 1
    },
    "top_error_sources": [
        {
            "source": "server",
            "count": 1
        }
    ],
    "first_timestamp": "2026-10-14T12:00:00+00:00",
    "last_timestamp": "2026-10-14T13:00:00+00:00",
    "skipped_lines": 0
}
```

| Поле отчета | Значение |
|---|---|
| `total_events` | Общее количество корректных событий |
| `events_by_level` | Количество событий каждого уровня, включая уровни с нулевым количеством |
| `events_by_source` | Количество событий каждого источника |
| `top_error_sources` | До пяти источников с наибольшим числом событий ERROR и CRITICAL |
| `first_timestamp` | Самая ранняя временная метка |
| `last_timestamp` | Самая поздняя временная метка |
| `skipped_lines` | Количество пропущенных ошибочных записей |

Для пустого входного файла количество событий равно 0, `events_by_source` содержит пустой объект, `top_error_sources` содержит пустой список, а обе временные метки равны `null`.

| `src/streamstats/analysis.py` | Подсчет статистики |

| `src/streamstats/errors.py` | Собственные исключения |

## Проверка проекта

После установки проекта и активации окружения:

```bash
python -m pytest
ruff check .
python -m streamstats --help
```

В проекте 16 тестов. Они проверяют оба формата, пустые файлы, Unicode, статистику, объединение нескольких файлов, ошибочные записи в обоих режимах, запуск CLI и неверный часовой пояс.

Для проверки настроенных хуков:

```bash
pre-commit run --all-files
```

Чтобы проверки автоматически выполнялись перед коммитом, один раз установите хук из каталога Git-репозитория:

```bash
pre-commit install
```

Если хук автоматически исправил уже добавленные файлы, нужно повторно добавить изменения и запустить проверку:

```bash
git add -u .
pre-commit run --all-files
```
